1. Product/Service Name

2. Proposal Purpose/Issues to be Solved
   Our project aims to develop an interactive AI dialogue system that allows users to have real-time conversations with famous historical figures. The system combines education and entertainment, helping users learn history in an engaging and personalized way.
   In modern education, students often find history lessons boring and disconnected from real life. Textbooks present facts and events, but they fail to convey the emotions, motivations, and decision-making processes behind historical figures. Our system addresses this gap by allowing users to “talk” directly with virtual versions of iconic individuals.
   This project aims to transform passive history learning into an interactive, curiosity-driven experience. It can be applied in schools, museums, and cultural education platforms to promote both knowledge acquisition and enjoyment.

5. Technical Implementation Methods (POC Demonstration Plan)

本節根據目前程式碼架構（前端採用 React + Vite + TypeScript，Tailwind CSS；狀態管理使用 Zustand；主要元件包含 `ChatWindow`、`InputArea`、`PersonaSidebar`）描述可執行的 POC 技術實作。POC 以 Ollama LLM API 為主要模型來源，並以本地模擬器作為離線 fallback。

架構設計

- 前端：React + Vite + TypeScript，UI 使用 Tailwind。主要元件：

  - `src/components/chat/ChatWindow.tsx`：對話視圖與捲動控制。
  - `src/components/chat/InputArea.tsx`：三個建議問題與輸入框，處理送出與 Enter 發送。
  - `src/components/chat/PersonaSidebar.tsx`：列出 persona，點擊切換會呼叫 store 的 `setPersona` 並開新 session（repo 已實作）。
  - CTA 與按鈕（`CTAButton`、`NavBar`、`LiveDemo` 等）已調整為可於新分頁開啟 `/chat`（`openInNewTab`）。

- 後端（POC）：輕量 Node.js/Express 或 Serverless function
  - 提供 `/api/chat/send` 端點，接收前端訊息並呼叫 Ollama API（或其他 LLM）；
  - 將 LLM 的回應以 SSE 或 WebSocket 串流回前端；
  - 若無外部 LLM 可用，代理端可回傳一個標示為「模擬」的串流或直接告知前端使用本地模擬函式 `simulateStreamingResponse`。

技術流程

- 使用者在 `InputArea` 發送訊息 → 前端 POST 到 `/api/chat/send`（包含 personaId, sessionId, message）→ 後端向 Ollama 發送 prompt 並以串流方式接收回應 → 代理端將 chunk 經 SSE/WebSocket 轉發給前端 → 前端呼叫 store 的 `updateStreamingContent` 逐步顯示回應，最後 `completeStreaming`。

Persona 與 Session 管理

- persona 定義保存在 `src/services/prompts`（例如 `persona.qinShihuang.ts`），包含 persona 的 prompt 與 metadata（id、name、description、anchors、expertise）。
- 切換 persona：`PersonaSidebar` 的按鈕會呼叫 `useChatStore().actions.setPersona(id)`，此 action 將更新 `personaId` 並執行 `startNewSession()`，以建立新的 session 並清空 messages（符合你要的行為）。

LLM（Ollama）設定要點

- 代理端需設定 Ollama API 相關參數（模型、temperature、max tokens、top_p 等）；可將 persona prompt 與會話歷史合併為一個 prompt 或以 conversation API 型式傳入。
- 若 Ollama 支援直接串流，代理可將 stream 直接轉為 SSE；若不支援，代理負責分段回傳或轉為 chunk 模擬。

驗證計畫（Acceptance Criteria）

- 使用者可在 1 分鐘內從首頁點擊 CTA（新分頁）進入 chat 並送出訊息。
- 前端能以 chunk-by-chunk 顯示 LLM 串流回應，最後呈現完整回答。
- 點選側欄 persona 將建立新 session 並顯示該 persona 的專長與重要事件。
- 當外部 LLM 不可用時，系統自動切換到本地模擬 (`simulateStreamingResponse`) 並保持展示流程不中斷。

風險與緩解

- LLM API 调用配额或网路不稳定：使用代理端缓冲、重试策略并切换至本地模擬器作为 fallback。
- 史實或敏感内容：在 persona prompt 与输出上加上明確標注，并在代理端加入簡易的输出过滤/guardrail（POC 可以规则式检查为主）。

後續擴充方向（POC 之后）

- 接入 LMS 保存學生會話與評分；
- 加入語音（STT/TTS）与多媒体资源（地图、图片）；
- 将 persona 管理移至 CMS，使非工程人員可编辑 persona 内容。
