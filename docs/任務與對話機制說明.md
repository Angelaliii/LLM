## 1. 流程總覽（S0-S5，Archive Repair Mode）

- S0: 任務選單（選擇要修復的歷史檔案）
- S1: 檔案解密室（視覺化殘缺檔案，定義待修復的關鍵欄位）
- S2: 選擇調查對象（選擇證人/NPC，帶入 persona 視角）
- S3: 深度訪談與線索收集（Guided Inquiry）
  - 顯示 Prompt Chips（事實/衝突/同理）
  - Notebook 於右側常駐，捕捉已獲線索並顯示 Knowledge Snippet
- S4: 檔案修復（將 Notebook 卡片拖入殘缺欄位並驗證）
- S5: 觀點驗證（Reflection，短答或 LLM 評估回饋）

設計核心：每個 Stage 的「破關」等價於修復一個殘缺欄位，系統依對話內容自動偵測並回傳 progress 事件給前端。

## 2. 任務資料結構（擴充說明）

位置：`frontend/app/data/missions/tainan-colonial-rule.ts`

新增/變更欄位建議（必填/建議）:
- `redactedFields`: 描述 S1 中的待填欄位（id、label、hint、linkedKnowledgeIds）
- `promptHints`: 初始 Prompt Chips 建議（可由後端動態覆寫）
- `verificationRules`: { mode: 'keyword'|'llm', requiredKeywords?: string[] }（S4 驗證策略）

Stage 定義保持，但建議補以下欄位：
- `type` 可擴充為 `repair`（對應拖拉驗證場景）
- `redactedFieldId?: string`（此 stage 若完成則填入特定檔案欄位）

## 3. 前端互動要點

- Prompt Chips：前端在輸入框上方顯示 3 個建議追問，來源可來自 mission 定義 (`promptHints`) 或後端回傳的 `promptChips`。
- Notebook：收到 AI 回覆或後端回傳的 `keyPointAchieved` / `notebookCapture` 時，自動在 Notebook 中新增卡片（卡片含 id、summary、sourceId）。前端應支援卡片高亮、編輯與拖拉操作。
- 拖拉驗證（S4）：玩家把 Notebook 卡片拖到檔案空格，前端呼叫 `POST /api/game/verify`（建議）或使用 `/api/game/chat` 的驗證模式來檢查是否正確；伺服器回傳 `verified` 與 `explain`，並在通過時回傳 `stageUnlocked`。

## 4. 後端回傳與 API 規範（建議）

`POST /api/game/start` 回傳應包含：
- `sessionId`, `missionId`, `npcId`, `redactedFieldsStatus`（哪些欄位 locked/unlocked）

`POST /api/game/chat` 回傳建議格式：
{
  responses: [...],
  knowledgeUsed: [...],
  promptChips?: [{ id, text, type }],           // 供前端顯示的追問選項
  stageUnlocked?: string,        // 若後端判定關卡解鎖
  keyPointAchieved?: { id, title, summary, sourceId },
  notebookCapture?: { id, text, sourceId } // 可直接加入 Notebook
}

此外，新增 `POST /api/game/verify`（建議）：檢驗玩家在 S4 的拖拉答案，回傳 `verified: true|false` 與 `explain`，並在成功時回傳 `stageUnlocked` 與可能的 `keyPointAchieved`。

## 5. 關鍵字檢測與進度回傳

- 關鍵點檢測（`checkKeyPointAchieved`）仍採關鍵詞比對為主，但建議把匹配結果與上下文片段一起回傳，讓 Notebook 顯示引用來源。
- 關卡解鎖（`checkStageUnlock`）：若匹配到必備關鍵字數量或達到 confidence 閾值，後端回傳 `stageUnlocked`，前端應立即觸發 store 更新並顯示提示卡。

## 6. 未串接 / 建議優先處理項目

1. 前端應處理 `stageUnlocked` 與 `keyPointAchieved` 回傳（SimpleChatRoom 加上 handler）。
2. 在 S3 加上 Prompt Chips 與 Notebook UI（容易提升學習引導性）。
3. 新增 `verify` API 或延伸 `/chat` 支援驗證模式，供 S4 拖拉檢查使用。
