這份文件將取代原有的 「使用者流程」 與 「技術架構」 相關章節。這套新架構稱為**「歷史檔案修復模式（Archive Repair Mode）」，專為國中生設計，旨在透過鷹架式探究（Scaffolding Inquiry）**降低操作門檻，同時保留歷史思辨的深度。

歷史檔案修復模式 - 系統設計文檔
🎯 設計理念：探究式學習 (Inquiry-based Learning)
本系統將學生定位為**「歷史調查員」**。學習不再是漫無目的的聊天，而是為了「修復一份殘缺的歷史檔案」。此模式解決了國中生常見的兩大痛點：

動機缺乏：不知為何而問 → 解法：賦予修復檔案的明確目標。

提問困難：不知如何追問 → 解法：提供多維度 AI 追問引導（Prompt Chips）。

📚 新版使用者流程詳解 (S0-S5)
🧩 S1 - 檔案解密室 (The Incomplete File)
情境設計： 學生進入任務後，不會看到冗長的文字介紹，而是一份**「視覺化的殘缺歷史文件」**（如：被塗黑的總督府報告、褪色的抗議傳單）。

使用者行為：

觀察殘缺文件，發現三個被標記為「待修復」的關鍵資訊（Key Information Gaps）。

例：[抗爭核心訴求]、[官方取締理由]、[非武裝手段]

系統提示：「為了還原歷史真相，請前往現場訪問關鍵證人。」

技術邏輯：

前端渲染 MissionIntro 組件，隱藏關鍵欄位（Blur/Redacted effect）。

初始化 NotebookStore，將這三個關鍵資訊設為 status: locked。

🗣️ S2 - 選擇調查對象 (Witness Selection)
使用者行為： 選擇不同的視角進入歷史現場。

例：選擇「抗爭學生」可得知訴求；選擇「警務課長」可得知官方理由。

🕵️ S3 - 深度訪談與線索收集 (Guided Inquiry)
這是系統的核心改變。將「純輸入」改為「輸入 + 引導選擇」。

功能 A：動態追問引導 (Prompt Chips) 在對話框上方，系統根據目前對話上下文，即時生成 3 個不同認知層次的追問選項：

🟡 事實層 (Fact)：詢問具體事件（如：「請願書裡面寫了什麼？」）

🔴 衝突層 (Conflict)：詢問對立面（如：「為什麼警察說你們是違法的？」）

🔵 同理層 (Empathy)：詢問個人感受（如：「這樣做你不怕連累家人嗎？」）

功能 B：即時筆記本 (The Notebook)

畫面右側常駐「檔案修復進度」。

當對話內容觸及 S1 的關鍵資訊時，系統觸發 Capture Event：

筆記本上的對應欄位解鎖，填入關鍵字。

顯示「✨ 已獲得線索」動畫。

附帶一則短歷史註解（Knowledge Snippet）補充背景。

📝 S4 - 檔案修復 (Archive Reconstruction)
使用者行為： 回到 S1 的殘缺文件介面。現在學生擁有了從 S3 收集到的線索碎片。

拖拉互動：將右側筆記本收集到的「關鍵概念卡片」，拖拉至文件中正確的空格。

邏輯驗證：如果填錯（例如將「武裝暴動」填入「手段」），系統會給予引導式錯誤提示（「提示：這次運動強調的是合法請願，非武力」）。

✅ S5 - 觀點驗證 (Reflection)
使用者行為： 完成檔案修復後，回答 1-2 題延伸思考題（非記憶性題目），確認對歷史脈絡的理解。
