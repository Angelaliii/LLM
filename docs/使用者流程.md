| 階段代號               | 使用者在做什麼                                     | 介面長怎樣 / 顯示內容                                                                           | 系統邏輯 & LLM / RAG 用法                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S0 – 任務選單          | 使用者選擇任務（例：E2 工業日本・農業臺灣）                     | 任務列表卡片：任務名稱、時代、難度、簡短介紹、已完成狀態                                                           | 前端從 `missions` 清單載入資料，不需要叫 LLM。使用者點選任務後，帶著 `missionId` 進入 S1。                                                                                                                                                             |
| S1 – 任務開場故事        | ✨ 1. 看到一小段故事背景  2. 被問「你想先問誰？」或「你覺得問題出在哪？」之類 | 畫面上：  - 故事敘述（1～2 段）  - 簡單插圖/時代標籤  - 下面一個「開始調查」按鈕，或 1～2 個引導問題                           | 系統根據 `missionId` 取出：背景 chunk（例如工業日本・農業臺灣簡介）。用一個「敘事者用 system prompt + RAG」生成：1. 150～200 字故事背景 2. 1～2 個引導式問題。儲存這段文字與任務狀態（state = S2）。                                                                                       |
| S2 – 選擇對話角色        | 使用者從 NPC 清單中選：技師 / 佃農 / 會社幹部…               | 顯示 NPC 卡片：頭像、名字、身分、一句介紹；點選後進入對話區。                                                      | 從 `missionId` 載入對應 `NPC` 列表，尚未叫 LLM。選到 NPC 後，記錄 `currentNpcId`，進入 S3。                                                                                                                                                     |
| S3 – 與 NPC 對話（可重複） | 使用者輸入問題，或點「推薦問題」跟角色聊天。可以多輪：問完技師再換農民。        | 畫面左邊：對話框（類聊天室），上方顯示目前對象：例「你正在與：山田清一（日本技師）對話」。右側：切換 NPC 的按鈕 / 目前任務提示條。                  | 🔹每次送出： 1. 依 `missionId` + 目前對話內容，做 RAG 檢索（抓 3～5 個相關 chunk）。 2. 將「NPC 角色卡 + RAG 結果 + 對話歷史」放進 system + messages，請 LLM 以該 NPC 身分回答。 3. 對話過程中累積「重點紀錄」（可以用一個 hidden 的 summary 欄位，每幾輪更新一次）。 🔹當使用者按「我覺得差不多了」或對話輪數超過某門檻時，進入 S4。 |
| S4 – 系統重述完整故事      | 使用者看到一段「整理過的版本」，像老師幫你收尾：把剛剛聊天的線索串成因果清楚的故事。  | 一個閱讀區塊：  - 標題：這次調查的全貌  - 文字：300～500 字，把日治農業政策、蓬萊米、糖業、農民處境串起來  - 下方一個按鈕「我準備好接受挑戰」→ 進入測驗 | 系統把：1. 任務核心 chunk（固定重點） 2. 對話摘要（剛剛學生問過什麼、NPC 回了什麼）一起餵給 LLM，下指令：「請用國中程度、條理清楚，幫學生整理一篇回顧」。這一段也可以存進 logs，當作學習歷程。完成後 state = S5。                                                                                               |
| S5 – 測驗（確認熟悉度）     | 使用者作答 3～10 題：單選 / 判斷 / 資料題。做完看到分數與解析。       | 顯示題目清單：一次一題或一次全部顯示。每題都有：題幹、選項、提交後顯示對錯與解析。最後有總結分數與稱號。                                   | 題目來源可以有兩種：1. 事先準備好的題庫（`e2Quizzes`），直接抽題。2. 用 LLM 根據核心 chunk 產新題，但建議人工審過後再入庫。作答時不需要再叫 LLM，只要前端核對答案並計算分數。完成後把：正確數、提示次數、作答時間等回傳後端紀錄。                                                                                         |
