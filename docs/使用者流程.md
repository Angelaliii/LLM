歷史任務制 AI 系統設計（使用 Ollama llama3.2-3b）
1. 使用者流程（User Flow v2）
流程總覽
S0 任務選單
 → S1 任務開場故事
   → S2 選擇對話角色
     → S3 NPC 對話（System 1）
       ↔ S3-EVAL 進度評估（System 2）
       → 條件達成 → S4 系統重述完整故事
         → S5 測驗與回饋

S0 – 任務選單（Mission List）

使用者在做什麼

從任務列表中選擇要挑戰的任務（例如：E2 工業日本・農業臺灣）。

畫面

任務卡片列表：

任務名稱

時代標籤（台灣史／中國史／世界史…）

難度

完成狀態、最高分數

系統行為

從前端 missions 靜態資料載入任務清單。

使用者選定任務後，帶著 missionId 進入 S1。

此階段不呼叫 LLM。

S1 – 任務開場故事（Narrative Intro）

使用者在做什麼

閱讀一小段故事背景。

理解本任務要解決的核心問題（例如：為什麼農民會抱怨種甘蔗給會社磅？）。

畫面

故事段落（約 150–200 字）。

時代／地點標籤（例：日治時期・嘉南平原）。

1～2 個引導式問題（例：「你覺得誰最清楚真相？」）。

按鈕：「開始調查」。

系統行為（LLM 使用）

從 missionId 取得「背景 chunk」與任務目標。

呼叫一次 LLM（llama3.2-3b）產生：

任務背景故事（System 1 用）

引導問題

將產生內容暫存於前端或後端 session 中。

轉入 S2。

S2 – 選擇對話角色（NPC Select）

使用者在做什麼

從 NPC 清單中選擇要先詢問的角色：

日本技師

佃農

製糖會社幹部 ……

畫面

NPC 卡片：

頭像

名字

身分標籤

一句簡介

系統行為

從 missionId 讀取對應的 npc 資料陣列。

將使用者選定的 currentNpcId 記錄在任務狀態。

進入 S3。

S3 – 與 NPC 對話（System 1：直覺聊天）

使用者在做什麼

以類似聊天視窗的方式，和選定的 NPC 來回對話。

可以多輪，並隨時切換 NPC。

畫面

左側：對話紀錄（你說／NPC 說）。

上方：目前對話對象（例：「你正在與：山田清一（日本技師）」）。

右側或下方：

NPC 切換按鈕

任務提示條（顯示已收集的關鍵線索數量）

系統行為（LLM 使用 – System 1）

每次使用者送出訊息：

將該任務的核心 chunks 做一次簡易 RAG 檢索（3–5 筆）。

取出當前 NPC 的 persona（角色卡）。

使用 llama3.2-3b：

system：角色設定與對話規則。

user：學生問題。

額外 context：RAG 檢索結果。

回傳 NPC 回應，加入對話紀錄。

累積 conversationTurns（對話輪數），並將本輪對話附加到 conversationSummary 中。

同時觸發 S3-EVAL（見下一節）。

S3-EVAL – 進度評估（System 2：慢思考老師）

在背景悄悄進行，不直接顯示給學生看。

觸發時機

每過 2～3 輪對話，或關鍵用語出現時（例如「覺得被剝削」「磅重不公」）。

系統行為（LLM 使用 – System 2）

將下列內容送給 LLM（同樣 llama3.2-3b，但 System 2 prompt）：

該任務的 learningGoals 列表（學習目標）。

目前 conversationSummary（壓縮過的對話摘要）。

要求模型只用 JSON 回覆：

每個目標標記：not_mentioned | wrong | partial | mastered

總結：masteredCount、partialCount、confidence（0–1）

前端／後端根據規則判斷是否「解得差不多」：

例如：

conversationTurns ≥ 6

masteredCount ≥ 3

confidence ≥ 0.7

系統結果

若尚未達標：

繼續停在 S3，NPC 對話照常進行。

若長時間未達標，可根據評估結果，讓 NPC 主動給出提示問題。

若達到門檻：

顯示一段提示（例：「看起來你已經掌握大部分線索，我們來整理一下故事吧！」）。

自動進入 S4。

這個階段就是「LLM 雙過程理論」中 System 2 的角色：
NPC ＝ System 1（陪你玩），評分老師 ＝ System 2（檢查理解）。

S4 – 系統重述完整故事（Mission Summary）

使用者在做什麼

閱讀系統整理過的完整故事，把剛剛對話得到的零碎線索串起來。

畫面

標題：例「工業日本・農業臺灣：糖業王國背後的真相」。

正文：300～500 字，條理清楚、國中程度。

重點列點（可選）：政策、技術、農民處境等。

按鈕：「我準備好接受挑戰」→ 進入測驗。

系統行為（LLM 使用）

將以下內容提供給 llama3.2-3b：

任務核心 chunks（穩定史實）。

learningGoals。

conversationSummary。

S3-EVAL 的評估結果（可選）。

要求模型產生：

一篇「符合課綱、國中程度、結構清楚」的回顧文本。

（可選）一版較精簡的 bullet 重點，用於 UI 高亮。

將這段文本存入 session（可做為學習歷程紀錄）。

S5 – 測驗與回饋（Quiz & Feedback）

使用者在做什麼

作答 3～10 題選擇題／判斷題／資料題。

看見自己的分數與解析。

畫面

題目卡片：

題幹

選項 A–D（或 O/X）

送出後顯示：

正確或錯誤

簡短解析

任務總結：

分數、等第、稱號

建議重看重點（例如指出哪個學習目標尚未掌握）

系統行為

題目來源：

主要使用事先設計好的 missionQuizzes。

若有使用 LLM 產題，需事先人工審查後寫入題庫。

作答時：

前端根據題庫中的 answer 判斷對錯，無需再叫 LLM。

計算：

正確題數

使用提示次數（若有）

作答時間

將結果上傳後端（或本機儲存）作為學習紀錄。

2.3.2 Ollama 呼叫封裝
// services/ollama.ts
export interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
}

export async function callOllamaChat(messages: ChatMessage[]) {
  const res = await fetch('/api/ollama/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      model: 'llama3.2:3b', // 依實際 ollama 模型名稱調整
      messages,
      stream: false,
    }),
  });

  if (!res.ok) throw new Error(`Ollama error: ${res.status}`);
  const data = await res.json();
  // 依實際回傳格式取出 content
  return data;
}

2.4 簡易 RAG（前端版，之後可搬到後端）
// services/rag.ts
import type { Chunk } from '../types/history';

// 極簡版：只用關鍵字與 topic 過濾
export function retrieveChunks(
  all: Chunk[],
  missionId: string,
  query: string,
  limit = 4,
): Chunk[] {
  const inMission = all.filter((c) => c.missionId === missionId);

  const scored = inMission.map((c) => {
    const hits = c.text.includes(query) || c.topic.includes(query) ? 1 : 0;
    return { c, score: hits }; // 之後可換成向量相似度
  });

  return scored
    .sort((a, b) => b.score - a.score)
    .slice(0, limit)
    .map((s) => s.c);
}

2.5 雙過程評估服務（System 2）
// services/progressEval.ts
import type { LearningGoal } from '../types/history';
import { callOllamaChat } from './ollama';

export type GoalStatus = 'not_mentioned' | 'wrong' | 'partial' | 'mastered';

export interface EvalResult {
  goals: { index: number; status: GoalStatus }[];
  overall: {
    masteredCount: number;
    partialCount: number;
    confidence: number; // 0~1
  };
}

export async function evaluateProgress(
  goals: LearningGoal[],
  conversationSummary: string,
): Promise<EvalResult> {
  const goalText = goals
    .map((g, i) => `${i + 1}. ${g.description}`)
    .join('\n');

  const systemPrompt = `
你是一位國中歷史老師，負責評估學生對某個任務的理解程度。
請根據【學習目標】與【對話紀錄】，只回傳 JSON 評分結果。
`.trim();

  const userContent = `
學習目標：
${goalText}

對話紀錄：
${conversationSummary}

請只用以下 JSON 格式回覆，不要多寫解釋：

{
  "goals": [
    { "index": 0, "status": "not_mentioned | wrong | partial | mastered" }
  ],
  "overall": {
    "masteredCount": 數字,
    "partialCount": 數字,
    "confidence": 0 到 1 的小數
  }
}
`.trim();

  const data = await callOllamaChat([
    { role: 'system', content: systemPrompt },
    { role: 'user', content: userContent },
  ]);

  // 依實際回傳格式解析 data.message.content 為 JSON
  // 這裡假設模型乖乖輸出合法 JSON
  const json = JSON.parse(data.message.content) as EvalResult;
  return json;
}

3. 小結

你現在的系統可以完全用 RAG + 角色卡 + LLM 雙過程 實現，
不需要微調模型。

使用者流程從 S0～S5 清楚對應到畫面與系統行為。

雙過程（System 1 / System 2）主要運用在：

S3：NPC 對話（System 1）＋背後的進度評估（System 2）

S4：故事總結（可先草稿再精修）
