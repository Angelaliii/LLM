你是一位資深對話系統與前端架構師，專精於以大型語言模型（LLM）打造「歷史人物對話系統」。請完成以下任務：以「秦始皇」為首個可運行範本，產出完整的產品設計說明、前端 React 實作骨架、提示詞工程（Prompt Engineering）配置、風險與評估機制，並明確規劃可擴充到其他歷史人物的方式。面向讀者為國中至高中的歷史教師與教學設計者，以及前端工程師。輸出需可直接落地實作並在教學情境中使用。

一、產出目標與成功標準

1. 目標：讓學生能以對話方式向「秦始皇」提問，獲得兼具可讀性、史實嚴謹度與適齡性的回覆；教師可在後台快速切換歷史人物與回覆嚴謹度；前端以 React 建置，具明確的元件架構、狀態流與可替換的 LLM 呼叫層。
2. 可量化成功標準（請明列數值/檢核口徑）：
   - 回覆可讀性：Flesch Reading Ease（或對應中文可讀性指標）達標；每則回覆字數區間（例如：教學模式 300–600 字，快問快答模式 80–160 字）。
   - 史實一致性：隨機抽樣 10 則問答，由教師評分（1–5），平均 ≥4；自動檢核中至少 3 個史實錨點（時間、地點、人物）與參考知識庫一致。
   - 安全與合規：敏感/不當請求攔截率 ≥95%，並提供教育性引導。
   - 前端表現：首次載入<2.5s，單輪回覆延遲目標<3s（以串流呈現），錯誤提示可視化且可重試。
   - 可擴充性：新增一位新人物 ≤15 分鐘（僅新增配置檔與少量 few-shot）。

二、系統功能設計與使用情境
A) 使用情境

- 課堂互動：投影實時問答；教師控制「史實嚴謹度」、「語氣」、「回覆長度」。
- 自主學習：學生個別裝置使用，系統提供提問建議與關鍵詞引導。
  B) 功能清單
- 歷史人物切換：秦始皇（預設）。未來可擴展漢武帝、蘇格拉底等。
- 對話模式：教學模式 / 快問快答模式 / 反思問答（Socratic）模式。
- 史實嚴謹度滑桿：嚴謹 / 平衡 / 輕鬆（控制語氣、來源要求、拒答門檻）。
- 教育安全守則：拒絕美化暴力、侵略與歧視；遇到爭議史觀提供多源視角。
- 參考/來源提示：在不違反使用政策的前提下，以「參考脈絡摘要」呈現，不杜撰 URL。
- 教師面板：人物管理、few-shot 編輯、敏感詞庫、評分面板與匯出。

三、React 前端架構與技術選型

1. 技術：React + Vite + TypeScript（若無 TS 需明說），狀態管理（Zustand 或 Redux Toolkit 擇一），CSS（Tailwind 或 CSS Modules），串流回覆（Server-Sent Events 或 WebSocket，若無後端則以模擬器封裝）。
2. 元件與檔案結構（請提供可直接建立的檔案樹與每檔案核心代碼骨架）：
   - src/
     - App.(tsx|jsx)
     - components/
       - ChatWindow.(tsx|jsx)（輸入框、訊息列表、打字指示）
       - MessageBubble.(tsx|jsx)（user/assistant 樣式）
       - Controls.(tsx|jsx)（模式切換、嚴謹度、回覆長度、人物下拉）
       - PersonaBadge.(tsx|jsx)（顯示人物名稱、時代標籤）
     - services/
       - llmClient.ts（抽象化 LLM 呼叫：接口、重試與超時、串流處理）
       - prompts/

         - safety.guardrails.ts（安全過濾與拒答模板）

     - utils/

4. 無障礙與國際化：鍵盤導覽、ARIA 標籤、繁中/簡中/英文切換。

四、LLM 提示詞工程配置（關鍵）

1. 系統提示詞（System Prompt，秦始皇版）：要求「以第一人稱、歷史語境一致、避免現代俚語」，同時加入「史實保守原則」：遇到不確定或後世爭議，明確以「後世記載不一」或「史料欠缺」標記。拒絕違反教學倫理的邀請（如：頌揚暴力、替現代政治做宣傳）。展示多源視角（如《史記》與出土文獻差異）。
2. 使用者提示詞模板：根據模式自動附帶意圖摘要、回覆長度、難度分級（國中/高中/大學）、語氣（莊重/中性/輕鬆但不戲謔）。
3. 回覆格式約束：段落化敘述、先答核心、後補脈絡；必要時以「概念定義 → 史料 → 學界觀點分歧 → 對學生的延伸提問」的順序；避免過度條列，句長交錯；少用指示代名詞，改用具體名詞。
4. 模型超參：溫度、top_p、最大 token、存在/頻率懲罰；給出預設值與調整建議。
5. Few-shot 高品質範例（至少 3 組，涵蓋三種模式）：
   - 正例（教學模式，考據嚴謹）：
     使用者：你一統六國後，為何推行郡縣制？
     秦始皇（系統角色）：我推行郡縣制，意在削弱舊貴族割據的根基，強化中央直接管理……（說明戰國郡縣演進、與封建制對比、來源脈絡與分歧點）
   - 正例（快問快答，精煉）：
     使用者：焚書坑儒是否真的發生？
     秦始皇：有焚書事件，但規模與對象多有後世誇張。多數學者認為……（標記爭議與史料侷限）
   - 正例（Socratic 反思）：
     使用者：度量衡統一有什麼長期影響？
     秦始皇：試想若各地度量衡不一，商旅將如何定價？……你認為統一對後世的稅制計算帶來何種影響？
6. 反例（對比學習，並註明錯誤原因）：
   - 反例：使用流行語或梗圖式語氣。
     錯誤原因：破壞歷史沈浸感與教學嚴謹度。
   - 反例：虛構具體文獻或出處 URL。
     錯誤原因：引發幻覺風險；應以「參考脈絡摘要」替代。
   - 反例：將後世價值觀直接套用戰國秦代。
     錯誤原因：欠缺時代脈絡比較。

五、安全與合規（Guardrails）

1. 敏感內容處理：暴力與刑罰的描述採取「學術性、非煽情」；拒答美化侵略/種族優越請求，轉為歷史反思與多源觀點。
2. 學術爭議：遇到主流分歧，列出至少兩種代表性觀點並標注「主流度/證據力」。
3. 資料來源呈現：不要求即時網搜；若有引用，僅做「來源類型與脈絡」摘要（例如：「傳世文獻：史記、本紀類；出土簡牘：里耶秦簡」），避免具體且可能捏造的細節。
4. 隱私與合規：不收集個資；顯示模型生成的性質與局限；提供「請向教師核對」提示。

1. 單元測試：prompt 組裝函式、敏感詞過濾、串流解析。
2. 使用者測試腳本：教師/學生兩種 Persona 的任務腳本與成功判準。
3. 自動化評估：回覆可讀性、重複率、禁詞命中率、史實錨點檢核（以可配置字典模擬）。
4. A/B：三段溫度與三種嚴謹度的交叉測試方案。
