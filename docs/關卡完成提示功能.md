
# 關卡完成提示功能（整合 Archive Repair Mode）

> 最後更新: 2025-12-04

此文件描述在「檔案修復」模式中，如何由對話與 Notebook 觸發關卡完成提示（Stage Completion），以及相關的 UI / API 行為。請參考 `docs/對話系統架構.md` 中的回傳欄位契約（`notebookCapture`, `stageUnlocked` 等）。

---

## 核心概念

- 關卡完成 = 成功修復一個被遮蔽（redacted）的檔案欄位。
- 完成條件可由 `requiredKeywords`、`notebookCapture` 或 LLM 驗證共同決定。

## 主要互動流程（摘要）

1. 玩家在 S3 與 NPC 對話，系統或玩家新增 Notebook 卡片（`notebookCapture`）。
2. Notebook 卡片累積到滿足 Stage 的驗證規則（`verificationRules`）時，前端會啟用 S4 的拖拉驗證界面。
3. 玩家在 S4 將卡片拖入檔案欄位並觸發驗證 API。
4. 驗證成功後，後端回傳 `stageUnlocked`、前端顯示 `StageCompletionCard`（恭喜卡片），並提供「留在本關 / 前往下一關」選項；若為最後一關則改為「前往總結」。

## 前端視覺與交互要點

- Notebook：顯示已捕捉的線索卡片、來源與簡短註解；新卡片會有短暫高亮動畫。
- StageCompletionCard（恭喜卡片）：包含關卡標題、完成說明、下一關預告、以及兩個主要操作按鈕。
- 若驗證失敗，卡片顯示建議追問（由 `promptChips` 提供）而非單純「錯誤」。

## 技術實現（關鍵）

### 新增 / 修改 API 建議

- `POST /api/game/verify`（建議）：
  - request: `{ sessionId, stageId, notebookCardIds }`
  - response: `{ verified: boolean, explain?: string, stageUnlocked?: string, keyPointAchieved?: {...} }`

- `POST /api/game/chat`：當後端判定有新的 `notebookCapture` 或 `stageUnlocked`，應直接回傳這些欄位，前端將自動加入 Notebook 與顯示關卡完成卡片。

### 前端處理範例（核心邏輯）

- 關鍵字檢測（S3）: 當收到 AI 回覆或玩家輸入，呼叫 `checkKeywordsInMessage` 並把 `notebookCapture` 訊息 push 到 Notebook。

```ts
function checkKeywordsInMessage(message, keywords) {
  return keywords.filter(k => message.includes(k));
}
```

- 關卡完成觸發（S4）: 驗證成功後延遲 800-1500ms 顯示 `StageCompletionCard`（給予視覺緩衝與動畫），並呼叫 store 更新狀態。

```ts
if (verified) {
  setTimeout(() => setShowCompletionCard(true), 1000);
}
```

## UX 設計要點（建議）

- 卡片動畫：scaleIn + shimmer + 小圖標彈跳
- 新發現線索：Notebook 中短暫的黃色閃爍（2s）以提示玩家
- 提示機制：若驗證失敗，顯示 1-2 個推薦 Prompt Chips 幫助玩家補強證據

## 注意事項

- 驗證策略需與任務設計一致：若採 LLM 驗證，需控制成本並限制最大重試次數。
- 保存 Notebook（localStorage）以便斷線後恢復。若資料敏感，需加密或 server-side persist。
