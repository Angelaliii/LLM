# 關卡破關機制（以現行程式行為為準）

> 文件版本: 2.0
> 最後更新: 2025-12-25

本文件描述「目前已實作」的破關／解鎖機制，並清楚標註尚未串接或尚未實作的部分。

---

## 名詞定義

- **解鎖 (unlock)**：從 S3 具備「可以前往 S4」的條件（可能由前端或後端判定）。
- **破關 (clear)**：在 S4 完成檔案修復（進度 100%）並進入 S5。
- **通關 (complete)**：在 S5 完成測驗／反思（依前端測驗流程為準）。

---

## 流程總覽（S0-S5）

- S0：任務選單
- S1：任務開場／情境導入
- S2：NPC 選擇（部分流程可能與 S3 合併）
- S3：訪談對話（蒐集線索、觸發關鍵點）
- S4：檔案修復（拖拉線索到缺漏欄位）
- S5：測驗／反思

---

## S3 → S4（解鎖條件：現況）

目前專案同時存在「後端解鎖」與「前端解鎖」兩條路徑：

### A) 後端：關鍵點累積 → 回傳 stageUnlocked='S4'（已實作，但前端未完整串接）

後端在每次 `POST /api/game/chat` 產生回覆後，會檢查是否達成 **關鍵點 (key point)**：

- `kp1`：六三法（總督專制）
  - 必備命中詞（任一）：六三法、法律第六十三號、63法、緊急律令、第63號
- `kp2`：警察制度（含保甲／連坐）
  - 必備命中詞（任一）：保甲、甲長、壯丁團、犯罪即決、連坐、警察大人、巡查

判定方式：把「玩家輸入 + NPC 回覆」合併成一段文字，只要命中上述必備詞，就視為新獲得該關鍵點，並回傳 `keyPointAchieved`。

接著後端會判斷：

- 已累積關鍵點數量 $\ge 2$ 時，回傳 `stageUnlocked: 'S4'`
- 若未滿 2 個，回傳 `stageUnlocked: null`

重要限制（現況）：

- 後端的 `stageUnlocked` 需要「持續累積的 keyPoints」才能運作。
- 目前前端呼叫 `/api/game/chat` 時 **未把 keyPoints 回傳給後端**，後端 session 也 **不會自動把新拿到的 keyPoint 存回 session**。
- 因此在現行串接下，`stageUnlocked` 很可能不會在實際遊玩中穩定觸發（`keyPointAchieved` 會出現，但累積不會生效）。

### B) 前端：評估或流程導覽 → 直接進入 S4（現行主要進入方式）

前端任務狀態在更新評估結果時，可能直接切換到 S4（例如：對話輪數與評估分數達標）。此外，部分 UI 流程也可能提供「前往下一階段」的導覽按鈕。

## S4（破關條件：檔案修復完成 → 進入 S5）

S4 的玩法是「把線索卡片拖到缺漏欄位」：

- 線索來源：主要來自 Notebook 的 `collectedClues`
  - 若 Notebook 沒有任何線索，S4 會提供一組預設線索卡（讓畫面可操作）
- 驗證方式：拖入後以「線索 id 或文字內容是否吻合」做比對
- 進度計算：以「缺漏欄位中已填滿的比例」計算百分比

破關（進入 S5）條件：

- **進度達到 100%** 後：
  - 會自動在短延遲後切換到 S5
  - 或由使用者按下「檔案修復完成 - 進入S5」按鈕切換

---

## 後端 API 回傳欄位（現況）

`POST /api/game/chat` 回傳資料中，和破關機制相關的欄位為：

- `keyPointAchieved?: { id, title, description }`
- `stageUnlocked: string | null`（可能為 `'S4'` 或 `null`）

現況未實作：

- 沒有 `POST /api/game/verify`
- 沒有 `notebookCapture` 欄位

---

## 前端事件處理（現況）

- 前端目前只對 `keyPointAchieved` 做反應：收到後會呼叫 `window.handleKeyPointAchieved(keyPoint)`（由聊天視窗層處理）。
- 前端目前**沒有**消化 `stageUnlocked` 來自動切換關卡。

---

## 建議的最小串接（若要讓「後端解鎖」成為真正破關機制）

若希望把「蒐集 2 個關鍵點 → 解鎖 S4」變成穩定可用的主路徑，建議最小改動如下：

1. 前端呼叫 `/api/game/chat` 時帶回 `keyPoints`（以及需要時的 `summaries`），讓後端 session 能更新。
2. 收到 `keyPointAchieved` 時，前端把它加入自己的 `keyPoints`，並在下一次請求回傳。
3. 收到 `stageUnlocked === 'S4'` 時，前端呼叫任務狀態的 `goToStage('S4')`（並顯示完成提示 UI）。
