# 關卡破關機制（對齊使用流程 V2：檔案修復導向）

> 文件版本: 1.1
> 最後更新: 2025-12-04

本文件將關卡系統改寫為「修復殘缺檔案」的流程說明：每個關卡（Stage）相當於檔案的一個待填欄位，玩家透過 S3 的深度訪談與 Notebook 收集線索，於 S4 拖拉驗證並完成修復。

---

## 流程重點（S0-S5 與關卡對應）

- S0: 任務選單（選任務）
- S1: 檔案解密室（視覺化殘缺欄位）
- S2: 證人選擇（選 NPC，帶入 persona 視角）
- S3: 深度訪談（Guided Inquiry）→ 收集關鍵字與筆記（Notebook）
- S4: 檔案修復（將 Notebook 卡片拖入空格並驗證）
- S5: 觀點驗證（Reflection／短答與 LLM 評估）

每個 Stage 的「完成」會觸發前端的進度更新與視覺回饋（例如 `StageCompletionCard`）。後端應在 `POST /api/game/chat` 中回傳 `stageUnlocked` 與 `keyPointAchieved` 以便前端同步狀態。


## Stage 定義（建議）

保留原本 Stage 欄位，但新增並明確化：
- `redactedFieldId?: string`：對應 S1 的某個檔案欄位（完成此 stage 即填入該欄位）
- `promptHints?: string[]`：初始 Prompt Chips 建議（會顯示於 S3）
- `verificationRules?: { mode: 'keyword'|'llm', requiredKeywords?: string[], minMatches?: number }`：S4 驗證策略

範例（E2）依舊保有 6 個 Stage，但每個 Stage 應標註 `redactedFieldId` 與 `verificationRules`，便於 S4 的驗證流程。

## 破關條件（實作建議）

1. 關鍵字匹配 + 筆記捕捉：S3 中若玩家或 NPC 回覆包含 Stage 所需 `requiredKeywords`（至少 2 個），後端回傳 `keyPointAchieved` 與 `notebookCapture`。
2. Notebook 匯總：Notebook 累積足夠證據後，前端允許玩家在 S4 拖入卡片進行驗證。
3. 驗證（S4）：呼叫 `POST /api/game/verify` 或使用 `/api/game/chat` 的驗證模式，由後端以關鍵字或 LLM 判定 `verified: true|false`；若通過，標記該 Stage 為完成並回傳 `stageUnlocked`。

## 前端/後端事件對應（必作）

- 後端回傳項目（`/api/game/chat` 或 `POST /api/game/verify`）:
  - `stageUnlocked?: string` — 被解鎖或完成的 stage id
  - `keyPointAchieved?: { id, title, summary, sourceId }` — 可直接加入 Notebook
  - `notebookCapture?: { id, text, sourceId }` — 建議前端自動存入 Notebook

- 前端處理：
  - 收到 `notebookCapture` 自動建立卡片並高亮新卡（動畫 2s）
  - 收到 `stageUnlocked` 呼叫 `useMissionStore.completeStage()` 並顯示 `StageCompletionCard`

## 驗證策略（S4）範例

- Keyword 驗證：檢查卡片內容包含 `verificationRules.requiredKeywords` 的數量達標
- LLM 驗證：將卡片文本 + mission context 丟給 LLM 進行語意判斷，回傳 `verified` 與 `explain`

## 錯誤處理與 UX 建議

- 當驗證失敗，顯示具體提示而非單純「錯誤」，例如指出缺少哪些關鍵證據或建議下一個追問的 Prompt Chip。
- Notebook 卡片應可編輯（補充玩家自行摘錄的註記），再重新驗證。

## 優先實作路線（建議）

1. 在 `SimpleChatRoom` 新增 Notebook UI 與 `notebookCapture` 的自動儲存處理（1 天）。
2. 實作 `stageUnlocked` 處理並呼叫 `completeStage()` 顯示 `StageCompletionCard`（半天）。
3. 實作 S4 驗證 API（keyword 驗證先行，LLM 驗證後補）（1-2 天）。

---

此版本聚焦於把關卡功能從「純文字關鍵字檢測」提升為可視化、可驗證的學習互動（Notebook + 驗證），以符合「檔案修復」的教學目標。
